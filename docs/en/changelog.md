## [0.4.0] - 2026-11-20

### Added
- Publishing (Phase 3, stage A; moved from Phase 5, ADR-025): buttons "Publikuj", "Cofnij publikację", "Archiwizuj" and "Przywróć" on the document page (plain forms, no JavaScript needed). Own documents need `documents.publish`; other people's need `documents.publish_any` (publish, unpublish) or `documents.edit_any` (archive, restore). Restoring leads to a draft. Publication is allowed in every processing status; the page warns when the content cannot be found by search, or only partly. A page shown before someone else changed the status cannot apply an action (409). Audited as `document.publish`, `document.unpublish`, `document.archive`, `document.restore` (identifiers and statuses only). Migration `documents_0004` (`published_at`, `published_by`, `archived_at`, check that a published document names its version). "Moje dokumenty" has a status column.
- Download of the original ("Pobierz oryginał", `/documents/<id>/download`) for everyone who can see the document: always saved as a file (`application/octet-stream`, `attachment`, `nosniff`, `CSP sandbox`, `private, no-store`), the file name in ASCII and exact UTF-8. Audited as `document.download`.
- `make probki` also writes the synthetic search corpus (`wyszukiwanie/`, 26 Polish and English documents) with `OCZEKIWANE-wyszukiwanie.txt` (target state of each file, queries and expected documents); the same corpus feeds the golden search tests.
- Search (Phase 3, stage B; ADR-026, ADR-027): page "Szukaj" (`/search`, permission `documents.read`) and a search field on the start page instead of the "being prepared" message; a plain GET form that works without JavaScript. Polish inflection, English, queries without diacritics, `"phrases"`, `-exclusion` (of the whole document) and `or`; numbers and codes found with or without separators (tax numbers, contract numbers, phone numbers with or without +48, codes such as IT-002, e-mail addresses, domains, IP addresses); typos in titles, file names, e-mail subjects and senders tolerated. Results grouped by document with a highlighted fragment and where it is ("strona 7", "załącznik: … › strona 2"), drafts marked "szkic", archived hidden unless "Pokaż zarchiwizowane"; filters for file type, language, author and dates; sorting by relevance or date; 20 per page, at most 50 pages; exact number of documents found. Visibility in SQL from `documents` (a Reader never finds drafts or archived documents). Time limit `SEARCH_TIMEOUT_MS` with results by date for very general queries. New variables `SEARCH_MIN_QUERY_CHARS`, `SEARCH_MAX_QUERY_CHARS`, `SEARCH_PAGE_SIZE`, `SEARCH_MAX_PAGES`, `SEARCH_TIMEOUT_MS`, `SEARCH_TRIGRAM_THRESHOLD`.
- Search index: tables `srch_parts` and `srch_documents` (migration `search_0002`), filled by the event `document.version.extracted` and, for documents processed before this version, at the first worker start; commands `baza-wiedzy search-check` and `baza-wiedzy reindex-search --all | --missing | --document ID | --version ID`. The `search` module now requires `ingestion`.
- `make perf N=<documents>` (manual, never in CI): search performance on a synthetic corpus with the production database settings — full index time and documents per minute, index sizes, query p50/p95, `EXPLAIN (ANALYZE, BUFFERS)`, 10 concurrent searches, evaluation of a Hunspell dictionary without diacritics (`docker-compose.perf.yml`, results in `perf-results/`).
- `make relevance DIR=… QUERIES=… AS=<user>`: local relevance check with your own documents and queries on the development stack (uploads drafts of that user, prints the first results with score, title, location and fragment, optional expectations); refuses paths inside the repository (it is public); typical names of such directories and files are in `.gitignore`.
- "Autor" column and author filter in "Moje dokumenty", and the author in search results, only for users who work with other people's documents (`documents.read_drafts`, `documents.publish_any` or `documents.edit_any`; ADR-030); for everyone else no author names, and an author parameter in the address is ignored.
- `baza-wiedzy users list` (login, source, active, roles, last login; no hashes or e-mails) and `baza-wiedzy users set-password <login>` for local accounts (asked twice or `--password-stdin`, never an argument; revokes sessions, clears login locks, audited as `user.password_reset_cli`; refused for Active Directory accounts). No password reset by e-mail (ADR-029).
- Guide for users and administrators: [user-guide.md](user-guide.md) (search syntax, inflection, numbers and codes, limits such as no synonyms, visibility, privacy, operator commands).

### Changed
- The owner of a document sees it in every state, archived included (Readers still never see archived documents).
- The role editor requires `documents.read_drafts` next to `documents.publish_any` and `documents.edit_any` ("wymaga: …" in the matrix, refused save with a message); roles saved earlier without it are marked "niespójna" and are not changed automatically.
- `make smoke` also publishes a file, finds it through the search page (inflected form and without diacritics), downloads it and checks that a search phrase reaches no log (proxy, app, worker, db) and that the proxy log holds no file name or CSRF token.
- The worker uses two database connections per process (`DB_POOL_SIZE=2` in `docker-compose.yml`): the search indexing runs while the outbox delivery holds its connection; with one the event was never delivered. The connection budget in deployment-operations.md is updated (30 of the default 40).
- Search is faster (ADR-028): at 20,000 documents p95 1,032 → 329 ms; identifier alternatives only when they differ from the query, ranking in the part's language first, matching in a narrow materialised step, exclusions through the GIN indexes, `work_mem` 16 MB per search. `markupsafe` declared directly in `pyproject.toml` (already locked through Jinja2, ADR-015).
- A document without any text (e.g. an empty TXT) says "Dokument nie zawiera tekstu" in the text panel instead of a bare "Nie wyodrębniono tekstu"; its status stays "gotowe" (processing worked) and it is found by title and file name.
- The search indexing at worker start runs in one worker process only (advisory lock); the others log that they skip it.
- `make relevance ONLY=1` counts only documents of the tested set ("N document(s) from the set, +M outside it").

### Security
- No search phrases, file names or tokens in logs (ADR-025): the proxy log (access and Caddy's own) drops query strings, `Referer`, `HX-Current-URL`, `Location`, `HX-Redirect` and `Content-Disposition` (names of downloaded files); the application access log drops query strings; database exceptions are logged without their message (PostgreSQL quotes the offending value) and SQLAlchemy hides bound parameters.
- **CSRF token in the proxy log (fixed)**: since Phase 1 (versions 0.2.0, 0.2.1 and 0.3.0) the Caddy access log recorded the request header `X-CSRF-Token` of every HTMX request (uploads, the extracted-text panel). The token belongs to one session and is useless after logout or expiry, but whoever could read the log could forge a request in a still open session. Operators: old proxy logs (`docker compose logs proxy`, at most 5 × 10 MB per container) may contain such tokens; treat them as confidential, or remove them after the update with `docker compose up -d --force-recreate proxy` (recreating the container discards its old log files).
- Responses that set their own security headers (downloads) keep them; no header is sent twice.

## [0.3.0] - 2026-11-17

### Added
- Document upload (Phase 2, stage A): page "Moje dokumenty" with search and live status, "Wgraj dokument" (JavaScript required; CSRF token in a header), document page. Files up to `MAX_UPLOAD_MB` (default 50; proxy limit `MAX_REQUEST_MB` now 51), type detected by content (ADR-021: PDF, DOCX, DOC, TXT, EML, MSG; other OLE2 files such as renamed `.xls` refused), stored under a random key on the `storage` volume via `.incoming/` and an atomic rename, read-only originals, sanitised file names, SHA-256, "possible duplicate" warning only against documents the uploader can see. New uploads are drafts visible to the owner and `documents.read_drafts` holders (others get 404). Tables `doc_documents`, `doc_versions`, `doc_email_metadata` (migration `documents_0002`). Audit `document.upload` (ids and hash only). Command `baza-wiedzy storage-cleanup`. New variables `MAX_UPLOAD_MB`, `STORAGE_DIR`.
- Document processing in the worker (Phase 2, stage B): TXT (UTF-8, Windows-1250, ISO-8859-2 by a fixed rule, ADR-022), EML (text or HTML body converted to text without running or fetching anything; attachments processed as separate parts with the origin "załącznik: nazwa › …", up to depth 3; unsupported attachments skipped with a note; damaged headers and dates tolerated; subject, sender, recipients, date and Message-ID stored and shown) and DOCX (paragraphs, tables, headers and footers; zip-bomb and XXE protection). Text split into chunks of at most 100,000 characters, language per chunk (Polish, English or unknown for short text, `LANGUAGE_MIN_LETTERS`). Statuses oczekuje → przetwarzanie → gotowe / błąd with readable messages; transient errors retried with an exponential delay, permanent ones fail at once; versions stuck in processing recovered; processing twice never duplicates parts. The document page shows the extracted parts, notes and e-mail headers. "Przetwórz ponownie" on the page (owner or `documents.edit_any`) and `baza-wiedzy reprocess <ID>… | --failed | --stuck`, audited as `document.reprocess`. Event outbox with `baza-wiedzy events redeliver`; the worker start re-enqueues waiting versions, recovers stuck ones, delivers events and removes orphaned temporary files. Tables `ing_parts`, `ing_results`, `ing_outbox` (migration `ingestion_0001`). New variables `INGEST_*`, `LANGUAGE_MIN_LETTERS`, `OUTBOX_RETENTION_DAYS`, `SCAN_HOOK` (virus scan step, off). `make smoke` uploads a file and waits until it is processed.
- PDF, DOC and MSG processing (Phase 2, stage C): PDF text per page ("strona N") in a child process with memory and time limits, scanned pages marked so that the document ends as "wymaga OCR" (OCR in Phase 4), page limit `INGEST_MAX_PAGES`; DOC through LibreOffice headless in a child process (private profile, 120 s timeout killing the whole process group, memory limit, one conversion at a time), then the DOCX extractor; MSG with subject, sender, recipients, Cc, date and Message-ID, plain/HTML/RTF body, attachments and attached messages up to depth 3. Password-protected PDF, DOC and DOCX fail (or are skipped as attachments) with a readable message; damaged files fail permanently; timeouts are retried. Protection against billion-laughs and deeply nested XML. `make probki DIR=…` writes synthetic samples of every case; `make smoke` also processes a text PDF; tests needing LibreOffice run in the new test image (target `test` of the worker Dockerfile, never released). New variables `INGEST_MAX_PAGES`, `OCR_MIN_CHARS`, `INGEST_CHILD_MEMORY_MB`, `INGEST_CHILD_TIMEOUT_SECONDS`, `LIBREOFFICE_MEMORY_MB`, `LIBREOFFICE_TIMEOUT_SECONDS`.

### Changed
- `make lint` also checks the GitHub workflows with actionlint (Docker image pinned by digest, shellcheck included), and `make test` parses the workflows and `dependabot.yml` (`tests/unit/test_github_config.py`).
- `worker`, `db` and `redis` run on the internal Docker network `backend` without internet access; `app` is on it and on `default` (proxy, Active Directory). New variable `BACKEND_SUBNET` (default `172.30.72.0/24`); `make smoke` checks the isolation (ADR-024).
- E-mails (EML, later MSG) uploaded without a title get the subject of the message as their title after processing; a typed title is never replaced (`doc_documents.title_source`, migration `documents_0003`). Case is never changed. Client-address handling behind Caddy documented, with a server check in Phase 7.
- The event `document.version.extracted` carries identifiers only and is delivered through the ingestion outbox; extracted text belongs to the `ingestion` module and search will read it through `ingestion.services.api` (ADR-020, open question 8 decided).
- The worker image contains `python-docx` and `lingua-language-detector` (about 300 MB larger); the app image does not. Development and CI install the `worker` extra (`uv sync --all-extras`).
- Worker image: `pypdfium2` and `extract-msg` (GPL-3.0, internal use only, ADR-015) added, unused `libmagic` removed (+3 MB). Documents uploaded earlier as PDF, DOC or MSG that ended with "Ten typ pliku nie jest jeszcze przetwarzany" are processed with "Przetwórz ponownie" (or `baza-wiedzy reprocess --failed`).

### Fixed
- CI did not start on the Phase 2 branch: an unquoted step name with `: ` in `.github/workflows/ci.yml` (since `3964b7f`) was a YAML error, so GitHub rejected the workflow file and ran no job. The CI quality job also makes sure `fonts-dejavu-core` (used for the PDF test files) is installed.
- The worker no longer fails its startup work when it starts before `baza-wiedzy migrate` (dev: `make up` then `make migrate`): it waits until the schema is at all migration heads, logging once a minute, then recovers and delivers events.
- File sizes below 1 KB are shown in bytes ("17 B" instead of "0.0 KB"); sizes use a decimal comma.
- Audit log: the details column is wider and long hashes are shortened (full value on hover and in the CSV export); the page area is wider.
- "Dodaj z wyprzedzeniem użytkownika AD": role checkboxes are next to their labels, aligned left.
- Admin panel forms (changing roles, activating users, revoking sessions, adding AD users in advance, roles, AD group mappings, audit CSV export) did not work in 0.2.0 and 0.2.1: every submit was refused with 403 (CSRF). Cause: the admin templates imported the `csrf()` macro without the template context, so the hidden token field was rendered empty; the tests did not notice because their helper copied a valid token from another form on the page (the logout form) instead of submitting the form under test. Fixed; every POST form is now tested with the token it renders. A refused request shows a page in the application layout with "Wróć na stronę główną" and "Zaloguj ponownie" and is logged with its reason (no token values).
- The title taken from an e-mail subject appeared only after reloading the document page: the page now updates the heading when processing ends (it was already stored), and `updated_at` changes with it.
- Sender, To and Cc have the same format for EML and MSG (`Name <address>`, separated by ", "); nested origins name "załącznik" once ("załącznik: a.msg › b.docx"); pages without a text layer show "brak warstwy tekstowej, wymaga OCR" instead of an empty expandable box; the footer is aligned with the content.


## [0.2.1] - 2026-11-17

### Security
- `opentelemetry-api` 1.45.1 → 1.45.2 (Dependabot alert #1, moderate: denial of service through quadratic parsing of the `traceparent` header), pulled in by FastAPI. Not exploitable here: FastAPI parses `traceparent` only when an OpenTelemetry provider is configured, and the application configures none (a test keeps it that way). Upgraded anyway through a per-package exception to `exclude-newer` (ADR-015); only this package changed in `uv.lock`.

### Changed
- Dependabot proposes only patch releases of the PostgreSQL 16.x and Python 3.12.x base images; a new PostgreSQL major or Python minor version is a planned migration with its own ADR (ADR-015). Docker PRs are checked by hand in the monthly review (no cooldown for Docker images).

## [0.2.0] - 2026-11-17

### Added
- `make smoke` (and the CI job `images`) also checks logging in through the proxy: break-glass admin created with a generated password, wrong password refused, login, admin panel, audit log, logout.
- Audit log viewer `/admin/audit` (permission `audit.view`): filters by date, actor, action and object, newest first, details as readable key-value pairs; CSV export of the current filters (UTF-8, `;`, protection against CSV injection, at most `AUDIT_EXPORT_MAX_ROWS` rows with a notice when cut), recorded as `audit.export`. GDPR/RODO description of the personal data processed; retention proposal (24 months) to confirm. Tests: role × endpoint matrix generated from the route list, security tests (account enumeration by content and time, foreign Origin, security headers).
- Admin panel `/admin` (Polish UI, works without JavaScript): users (search, filters, pages; AD users created in advance; activate/deactivate with immediate session revocation; manual roles; revoke sessions), roles with a permission matrix (Admin always full and read-only; system roles cannot be deleted; deleting a role in use shows the affected users and needs confirmation), AD group → role mapping (DN validation, confirmation for Admin, optional lookup in AD), system view. An admin cannot deactivate themselves or drop their own Admin role, and the last active admin is protected (also in the new command `baza-wiedzy user-active`). Every change is audited with before/after. Navigation built from module manifests. A test fails for any route without a login or permission check.
- Login with Active Directory (`LDAP_ENABLED=true`, off by default): LDAPS with mandatory certificate verification, users created at first login and identified by `objectGUID`, accounts created in advance linked by name, AD groups mapped to roles at every login (optionally nested groups), one account for `FIRMA\jan`, `jan@firma.local` and `jan`, same error message and limits as local logins, "temporarily unavailable" message and audit `auth.ad_unavailable` when AD cannot be reached (the local admin keeps working). New command `baza-wiedzy ad-check` and a documented test procedure for a real AD. New `LDAP_*` variables; `./secrets/ldap/` is mounted in `app`.
- Login with a local account (`/login`, `/logout`): server-side sessions with rotation at login, idle (120 min) and absolute (12 h) limits, CSRF protection for every state-changing request, failed-login limits per name, name + address and address (`baza-wiedzy unlock-login`), one generic error message, security headers (CSP), client address only from the proxy's fixed address (`DOCKER_SUBNET`, `PROXY_IP`). All pages except `/login`, `/health`, `/ready` and static files need a session. The application refuses to start with a `SECRET_KEY` shorter than 32 characters.
- `baza-wiedzy create-admin <name>` creates the local break-glass admin or resets its password (asked twice, or `--password-stdin`); Argon2id with a limit of concurrent hashes; 14-256 characters; audited as `cli.create_admin` / `cli.reset_password`. New variables `LOCAL_PASSWORD_MIN_LENGTH`, `LOCAL_PASSWORD_MAX_LENGTH`, `ARGON2_MAX_CONCURRENT`.
- Database tables of the core for Phase 1 (migrations `core_0002`, `core_0003`): `users`, `roles` with the system roles Admin, Publisher and Reader, `role_permissions`, `user_roles`, `ad_group_role_map`, `sessions` and the append-only `audit_log` (a trigger rejects UPDATE, DELETE, TRUNCATE). Migration `documents_0001` grants `documents.*` permissions to Publisher and Reader.

### Changed
- Release workflow refuses a tag whose commit is not on `main`.
- The application reports its version from the installed package (`pyproject.toml`); `APP_VERSION` only selects the image tag in `docker-compose.yml` and is no longer passed to the containers. `.env.example` now uses `APP_VERSION=0.1.0`.

## [0.1.0] - 2026-11-12

### Added
- Dependabot configuration (GitHub Actions SHAs, Docker base images, Compose images monthly with a 14-day cooldown; Python security updates only). Deployment docs: GHCR packages are private, the server needs a token with `read:packages`.
- CI (`ci.yml`): lint, types, module boundaries, unit tests, docs check, integration tests with PostgreSQL and Redis, image build for `linux/amd64` and a smoke test of the production Compose file (`make smoke`). Release workflow (`release.yml`, prepared, not run): checks tag against `pyproject.toml` and changelogs, publishes four images (`app`, `worker`, `db`, `proxy`) to GHCR with commit labels (ADR-017). Offline bundle script with all six images. Redis and ClamAV pinned by digest; proxy host ports configurable (`HTTP_PORT`, `HTTPS_PORT`). The application version comes from `pyproject.toml`.
- Logs are JSON lines (`ts`, `level`, `logger`, `message`, `process`, `exc`) from `app` and the worker processes; new variable `LOG_LEVEL`.
- `baza-wiedzy migrate` applies the migrations of all modules, independent of `ENABLED_MODULES`; `/ready` compares the schema with all migration heads. Dependency policy: security-fix exception and monthly review (ADR-015).
- Worker (Dramatiq on Redis): `WORKER_PROCESSES` processes with one thread and one database connection each, heartbeat in Redis checked by `/ready` (`worker`), test job `core.ping` and the command `baza-wiedzy worker-ping`.
- Database migrations: `baza-wiedzy migrate` (and `make migrate`) applies the `core` branch (extensions `pg_trgm`, `unaccent`) and the `search` branch (Polish dictionary, configurations `pl` and `simple_unaccent`) as the non-superuser application role; `/ready` reports the schema state (`not migrated`, `outdated`, `ok`). `make revision branch=<branch> m="..."` creates a migration in a module's branch. Golden search tests now run on the real migrations.
- Web application (FastAPI): start page in Polish with the configured `APP_NAME` (Jinja2, HTMX served locally, gettext catalog `pl`), `/health`, `/ready` (database and Redis checks; JSON, 503 when a check fails) and an HTMX status fragment. New command `make messages`. Dependency resolution only picks releases older than a fixed date (`exclude-newer`).
- Redis requires a password (`REDIS_PASSWORD`, new variable). The file volume is named `storage` and mounted at `/data/storage`. In development `app` and `worker` stop after 3 failed starts instead of restarting forever.
- Docker Compose stack (`docker-compose.yml`, `docker-compose.dev.yml`): proxy (Caddy, non-root, TLS modes `internal`/`files`/`acme`), app, worker, db, redis, optional `antivirus` profile (ClamAV); log rotation, memory limits, explicit `max_connections`; app and worker images (non-root; worker with Tesseract `pol`+`eng`, OCRmyPDF, LibreOffice Writer); the `db` image creates a non-superuser application role on first start. New variables in `.env.example`.
- Polish dictionary spike done: Hunspell is sufficient (results, measured memory and gaps in `search.md`, ADR-016). Golden search tests in `tests/search_golden/` and `make test-db`, which runs them against a throwaway database in Docker without publishing a port.
- Database image `docker/db` (PostgreSQL 16.15 on Debian 13) with the Polish Hunspell dictionary (`pl_pl.dict`, `pl_pl.affix`, UTF-8), the project's `polish.stop` list and the dictionary licence file; `docker/db/spike.sql` is a diagnostic script for the dictionary.
- Repository skeleton: Python 3.12 project managed with `uv`, `Makefile` as the single command entry point, pre-commit (ruff, mypy), `.env.example`, LF line endings.
- `scripts/check_docs.py` and `make docs-check`: verify that the English and Polish documentation (including `modules/`) have the same files, headings and header lines, that both changelogs have `[Unreleased]`, and that every module in `src/baza_wiedzy/modules/` has a page in `docs/en/modules/` and `docs/pl/modules/`.
- Modular structure: always-on core plus modules `documents`, `ingestion`, `search` (empty manifests for now) selected with `ENABLED_MODULES`; dependency check at startup with readable errors; permission catalog assembled from module manifests; in-process event bus; module boundaries checked by import-linter in `make lint`.
- Documentation of the modular design: ADR-013 to ADR-015, module pages in `docs/*/modules/`, new sections in architecture, data model, deployment and operations.
- Planned table names now carry a module prefix (`doc_*`, `srch_*`, `ing_*`); the indexed text table is `srch_parts` (was `document_parts`). Documentation only; no tables exist yet.
- Project guide `CLAUDE.md` and bilingual documentation set (architecture, data model, search, ingestion and OCR, authentication and permissions, deployment and operations, decisions, roadmap).
